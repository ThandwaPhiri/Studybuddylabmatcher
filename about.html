About Study-Buddy Lab Matcher

A focused, real-time platform that helps students find face-to-face lab partners quickly and safely — with campus-verified venues and a 3-tap posting flow.

🔬 What is Study-Buddy Lab Matcher?

Study-Buddy Lab Matcher connects students who need a lab or practical partner in a time-limited academic environment. Post a request in under 3 taps, browse live requests filtered by module, and get matched with a verified peer at a campus-approved venue — all without leaving the site.

Key Features

Everything built to solve one problem fast

⚡
Quick-Tap Posting
Post a partner request in 3 steps — module, venue & time, then confirm. No account setup, no forms to fill out twice.
🔴
Live Status Indicators
Every request shows a real-time Open or Matched badge so you never waste a click on a filled post.
🎛️
Module Filtering
Filter the request feed by course code to instantly see only the requests relevant to your academic track.
🔒
Safety Constraints
Venues are restricted to a verified list of campus locations only. No free-text entries, no off-campus meetups.
👤
Identity & Accountability
Every post is tied to a campus username — no anonymous requests, so all interactions remain accountable.
📱
Mobile-First Design
Tap targets are at least 44×44px, layouts reflow on small screens, and the interface works with a single thumb between lectures.

Accessibility

Built to WCAG 2.0 POUR standards

Principle Requirement How it's implemented
Perceivable Text alternatives (1.1.1) All icons use aria-hidden="true"; meaningful images carry alt text.
Perceivable Contrast ≥ 4.5:1 (1.4.3) All text/background combinations pass. Blue #2563eb on white = 5.9:1.
Perceivable Not colour alone (1.4.1) Status badges use colour + text label + dot symbol — never colour alone.
Operable Keyboard accessible (2.1.1) All interactive elements are reachable via Tab in a logical order with visible focus indicators.
Operable Target size ≥ 44×44px (2.5.5) Every button, chip, and link meets the minimum touch target size.
Understandable Readable language (3.1.1) Plain English throughout. lang="en" set on every page.
Understandable Descriptive errors (3.3.1) Error messages are specific: "Please select a module before continuing."
Understandable Visible labels (3.3.2) All form fields use visible <label> elements linked by for/id.
Robust Semantic HTML (4.1.1) <nav>, <main>, <section>, <footer> used throughout.
Robust ARIA (4.1.2) role, aria-label, aria-live, aria-current, aria-pressed, aria-required applied to all interactive components.
Study-Buddy Lab Matcher — Campus-verified venues only. Built with accessibility in mind.
